## Власність — серце спокою

Уявімо, що ми в бібліотеці вночі. Книги стоять на полицях, і кожна має своє місце. Ти можеш узяти книгу, почитати її, а тоді або повернути на місце, або — якщо це твоя книга — тримати в себе. Але жодна книга не може бути одночасно в руках у двох людей назавжди, і якщо ти віддав свою книгу другові «назавжди» — вона тепер його. Якщо ж дозволив лише почитати — вона твоя, і вона повернеться.

Це і є власність у Rust. Це найважливіша ідея мови, і вона простіша, ніж здається, бо ми всі живемо з нею щодня.

## Один власник

Кожне значення в Rust має рівно одного власника в кожен момент часу. Це не порада і не стиль — це правило, яке компілятор перевіряє на кожному кроці.

```rust
let book = String::from("Тихі сторінки");
let friend = book;
```

Дивись уважно на другий рядок. Коли ми присвоюємо `book` змінній `friend`, значення типу `String` *переміщується*. Відтепер власником тексту є `friend`, а `book` більше не існує для компілятора. Якщо ми спробуємо скористатися `book` після цього:

```rust
println!("{}", book); // компілятор це зупинить
```

компілятор відповість наполегливо: «value borrowed here after move» — значення було позичене тут після переміщення. Це не крик, це ввічлива пам'ятка: книга, яку ти віддав, тепер не твоя. Не переймайся, що буде нею — тепер це турбота іншого.

Тут важливо усвідомити, чому так. `String` живе в купі: вона не вміщується в змінну як число; змінна тримає вказівник на місце, де лежить текст. Якби і `book`, і `friend` тримали той самий вказівник, то коли кожен по черзі завершив би роботу, обидва спробували б звільнити ту саму пам'ять — двічі. У Rust такого не буває, бо власник один. Один власник — одне звільнення — жодної двійної помилки.

## Копіювання, коли це безпечно

Але ж бувають типи, які настільки прості, що їх легко просто сколіювати. Числа, символи, прапорці — для них переміщення і копіювання не відрізниш. Rust дозволяє цим типам копіюватися автоматично:

```rust
let x = 42;
let y = x;    // копіюється, а не переміщується
println!("{} {}", x, y); // обидва живі та здорові
```

Тип, що копіюється, позначається спеціальним трейтом `Copy`. Це як папірець, який легко надрукувати двічі: числа, `bool`, `char`, кортежі з таких значень. А от `String` не копіюється мовчки — з нього копіюють виключно явно через `clone()`:

```rust
let a = String::from("спокій");
let b = a.clone();
// тепер два спокій, і кожен має свого власника
```

`clone()` — це чесність: ти визнаєш, що створюєш другу копію, і платиш за неї — рівно стільки роботи, скільки триває.

## Повернення власності

Функції в Rust багато що приймають і багато що повертають. Якщо функція приймає значення, вона стає його власником — на час роботи, а якщо вона його повертає, власність повертається з нею:

```rust
fn make_spare() -> String {
    String::from("запас")
}

fn take_and_give(s: String) -> String {
    format!("{s}, але повернено у відповідь")
}

fn main() {
    let s = make_spare();
    let s = take_and_give(s);
    println!("{s}");
}
```

Поміть, як у `main` затінення знову служить нам: старий власник виходить, новий заходить, і ми ніколи не володіємо двома рядками зараз.

## Позичення — дивитися, не брати

Частіше ніж переміщати щось, ми хочемо лише подивитися: порахувати слова, прочитати довжину, порівняти. Для цього Rust дає позичення — `&`:

```rust
fn count_words(text: &String) -> usize {
    text.split_whitespace().count()
}

fn main() {
    let title = String::from("Тиха книга");
    let words = count_words(&title); // позичили, не забрали
    println!("{title} має {words} слів.");
}
```

Амперсанд говорить компілятору: «ця функція лише дивиться, і значення залишиться там, де було». Власник не змінюється. Безкінечно багато людей можуть одночасно позичати книгу для читання — поки ніхто не пише в ній.

## Позичання з правом змінювати

Іноді позичити — означає змінити. Для цього є *mut ref* — `&mut`:

```rust
fn add_postscript(text: &mut String) {
    text.push_str(", і спокійно далі");
}

fn main() {
    let mut note = String::from("Нічна думка");
    add_postscript(&mut note);
    println!("{note}");
}
```

Тут ми даємо функції ключ: «бери, але поверни так само, як зараз, тільки змінену». І тут важливе правило тиші: **або** багато читачів, **або** один письменник. Rust не дозволяє одночасно тримати `&mut` і будь-яку іншу позику до того самого значення — бо поки хтось олівцем править сторінку, ніхто не має читати з-під олівця.

```rust
let mut s = String::from("с");
let read = &s;        // читаю
let write = &mut s;   // компілятор зупинить: не можна одночасно
```

Це не обмеження, а гігієна: одночасно читати і редагувати — це як читати книгу, яку хтось очима пише. Rust каже: спершу закінчи одно, потім почни інше. Спокій ціною маленької уваги.

## Висилання в нікуди

Є ще питання: а якщо ми хочемо повернути посилання з функції? Це можна, але з обов'язковим поясненням — *часом життя*, і цьому присвячена наступна глава. Сьогодні ж запам'ятай головний образ:

Посилання — це гість. Гість не може жити в домі, якого немає. Якщо функція повертає посилання на щось, воно не може вказувати на те, що померло разом із функцією. Rust слідкує за цим холодно і безжально — і тому ми спимо спокійно, бо знаємо, що не тримаємо в руках уламки вже знесених будинків.

## Чому нас це стосується особисто

Можливо, зараз здається, що власність — це набір правил. Але подивись глибше. Цей механізм — єдина у своєму роді спроба мови сказати: *життя даних передбачуване*. Коли ти пишеш програму на Rust, ти рідко кажеш «може, десь витіче», «може, хтось не звільнить», «може, хтось уже звільнив». У Rust більшість таких «може» викреслено зі світу ще до запуску.

А той, хто викреслює тривогу, — дозволяє тобі думати лише про те, що справді важливо: про зміст. Оце і є тиша Rust.

## Власність у дії: переміщення

Ми вже зустріли переміщення, коли `String` відправили другові. Тепер розглянемо його ближче, бо воно трапляється набагато частіше, ніж здається. Кожного разу, коли ти передаєш значення функції, віддаєш його в колекцію або присвоюєш новій змінній, — ти зрушуєш власність.

```rust
fn main() {
    let title = String::from("Тихі сторінки");
    consume(title);           // власність переїхала всередину
    // println!("{title}");   // тепер неможливо: title порожній
}

fn consume(s: String) {
    println!("Я володію рядком: {s}");
}
```

Після `consume(title)` змінна `title` більше не володіє текстом — вона порожня. Якщо спробуєш її роздрукувати, компілятор зупинить програму ще на збірці. Це не покарання, а навчання: ти сам зважився, і мова лише визнає факт.

Чому це правильно? Бо коли `consume` завершиться, її параметр `s` піде зі сцени — і разом із ним піде й текст. Якби `title` продовжував «жити», ми мали б два імені для одного тексту, і обидва претендували б на його звільнення. Rust не хоче розділяти відповідальність: у нього один господар на одну річ.

## Повернення — це подарунок

Щастить, що ж власність можна *повернути*. Функція, яка прийняла значення, може віддати його назад:

```rust
fn give_back(text: String) -> String {
    println!("Тримаю рядок: {text}");
    text
}

fn main() {
    let s = String::from("лист");
    let s = give_back(s);   // s знову наша, знову жива
    println!("{s}");
}
```

Це як позика друга, який повертає книгу: кілька моментів вона була «в нього», але ось знову на нашій полиці. Rust не вимагає магії — лише чесність: якщо хочеш повернути, повертай виразом з останнього рядка функції.

На практиці така схема з'являється рідко, бо гарні рішення частіше *позичають* значення, ніж передають у повне володіння. Але розуміти механізм важливо: коли ти бачиш, що функція «забирає» і «повертає», — ти розумієш, чому компілятор так наполягає.

## Кілька гостей одночасно

Позики на читання можна множити без мертвої петлі. Уяви бібліотечну кімнату, де книгу можуть читати кілька людей одразу — усі дивляться, ніхто не пише:

```rust
fn main() {
    let story = String::from("спокійна глава");
    let first = &story;
    let second = &story;
    let third = &story;
    println!("{first}");
    println!("{second}");
    println!("{third}");
}
```

Три погляди на один текст — і ніхто не заважає. Читання безпечне, тому читачів можна кликати скільки завгодно. Rust так і дозволяє: необмежені `&T`, поки немає `&mut T`.

А от якщо хтось захоче ще й писати, Rust спохмурніє. Спробуємо передати `&mut` разом із читачами:

```rust
let mut text = String::from("глава");
let reader = &text;
let writer = &mut text;   // компілятор зупинить
```

Бо якби було дозволено, письменник міг би змінювати текст у ту саму мить, коли читач його читає: хтось тримає абзац 5, а текст уже став іншим. Rust каже: спершу заверши читання, потім пиши. Це правило просте й зберігає спокій.

## Межа позики: де живе позичка

У глави про час життя ми пірнули раніше; тут лише швидко окреслимо чому позика не може пережити свій дім. Позичка — це не копія, а погляд. Як тільки будинок (значення) пішов зі сцени, погляд не має на що дивитися.

```rust
fn problem() -> &String {
    let local = String::from("зникне");
    &local     // станеться помилка: local помре разом зі функцією
}
```

Компілятор тут не сперечається — він знає напевно: `local` існує лише всередині функції. Тож повернення позички на небуття було б безглуздям. Цей механізм називають «запозиченням» і правило таке: позичка живе, поки живе те, на що вона позичена.

## Глибоке копіювання: коли потрібна друга кімната

Колись хочеться не позичити, а мати справді *свою* копію. Для цього існує `clone()`:

```rust
let original = String::from("мій текст");
let copy = original.clone();
println!("{original} — {copy}");
```

Тут два тексти, дві кімнати, два господарі. `clone` явно копіює значення глибоко: для тексту — всі символи, для складних структур — усю вкладеність. Платиш за зрозумілість: ти робиш копію свідомо, і читач коду бачить, де саме сталася робота.

Цінність `clone` у тому, що він не приховує роботи. Коли бачиш `clone`, ти знаєш: тут пам'ять на коротку мить поповнилась, це коштує часу. Rust не робить копіювання потайки для складних типів — інакше ти ніколи б не знав, де програма мовчки сповільнюється.

## Зручні трюки з рядками

Тепер застосуємо мову власності до рядків — коли належить користуватися позичкою, а коли копією.

Довжина тексту, перше слово, пошук — усе це можна зробити через позичку, не чіпаючи господаря:

```rust
let phrase = String::from("довгий рядок вечір");
let len = phrase.len();               // скільки байт
let first_word = phrase.split(' ').next();  // перше слово
```

Методи, які лише «читають», приймають `&self` — позичку на самого себе. Ти тримаєш господаря, а методи лише зазирають. Славно: можуть читати сотні разів, і жодного разу не відберуть у тебе власність.

Змінюючі ж методи вимагають `&mut self` — ти мусиш мати ключ `mut`:

```rust
let mut log = String::from("нотатки: ");
log.push_str("додано ще один фрагмент");
```

Відчуй різницю: `len()` і `split()` приходять подивитися, `push_str()` приходить змінити. Мова сама розповідає, хто гість, а хто господар, — написано прямо у сигнатурах методів.

## Член сім'ї: повернення з умовою

Інколи власність можна повернути з умовою — наприклад, лише якщо щось вийшло. Саме тут нам допомагає `Result`, з яким ми зустрічалися раніше. Коли функція «може щось дати або ні», вона повертає `Result`, і всередині лежить або значення, або пояснення:

```rust
fn first_word_owned(text: &str) -> Result<String, String> {
    match text.split_whitespace().next() {
        Some(word) => Ok(word.to_string()),
        None => Err("порожній рядок".to_string()),
    }
}
```

Функція позичає вхідний рядок (через `&str`), але віддає власну нову копію (`String`), загорнуту в `Ok`. Позичка не порушилася: вхід лишився недоторканим, а результат став господарем власного тексту. Це звітність красивого коду: входи — позики, виходи — нові доми.

## Переміщення в дії: що насправді відбувається

Коли ти пишеш `let a = String::from("привіт"); let b = a;`, то `a` більше не існує для використання. Це не «поставили порожньо», це *перенос права*. У пам'яті так і лишився один об'єкт; просто тепер він належить `b`. Хтось каже «String не реалізує Copy» — це точна фраза, і вона пояснює, чому гратися в переміщення небезпечно, якщо не розуміти, що це передача, а не дублювання.

Числа — інша історія: `let x = 5; let y = x;` — тут `y` копіює 5, і `x` теж лишається живим. Числа реалізують `Copy`, бо копіювання п'ятірки нічого не коштує. Це те, що автори мови називають «маленькі типи, які легко дублювати, не боячись». Коли ти пишеш код і не впевнений — подумай: «це дешево скопіювати?» Якщо ні — це переміщення.

## Володіння в аргументах функцій

Володіння не лише про змінні нашої функції — воно тече через виклики. Коли ти передаєш значення в функцію, ти *даруєш* його функції (якщо не передумуєш), а коли позичаєш — лишаєш собі.

```rust
fn price_label(price: String) -> String {
    format!("Ціна: {price}")
}

fn main() {
    let cost = String::from("99.00");
    let label = price_label(cost);
    // після цього рядка cost уже не можна читати
    println!("{label}");
}
```

Тут `cost` переїхав у функцію. Якби нам потрібен був `cost` після виклику — довелося б позичити: `fn price_label(price: &str)`. Позичка `&str` не забирає `cost`; вона лише показує текст функції. Це вибір автора — і Rust підтримує обидва шляхи, бо перевіряє, що все узгоджено.

## Позички як двері

Уявімо будинок: власник ключів, а позичка — це тимчасова перепустка гостя. Гість не може виселити власника, але може оглянути кімнати. Позичка `&T` — огляд без змін; `&mut T` — огляд з правом переставляти меблі, але тоді інші гості не можуть заходити в цю кімнату одночасно.

Правило просте: або багато читачів без змін (`&T`), або один «господар» зі змінами (`&mut T`), але не обидва в один час. Це не каприз мови — це відмова від плутанини, яка в інших мовах веде до непередбачуваних багів. Rust обирає тишу: у кімнаті або спокійно читають, або рішуче змінюють, але не разом.

## Тимчасові значення та виразкові позички

Інколи позичка виникає «на льоту» — для одного виразу, і зникає відразу. Це нормально і навіть зручно: Rust ретельно стежить, що тимчасове не «переживе» свого використання.

```rust
fn display(s: &str) {}

// тимчасовий &str передається, а після рядка зникає
display(&String::from("швидкий текст"));
```

Тут `String::from(...)` створює володарний об'єкт, `&` позичає його функції, а до кінця виразу об'єкт зникає. Rust посміхається: тимчасові значення живуть рівно стільки, скільки треба, і вмирають саме вчасно. Це одна з тих «магій», яка стає зрозумілішою після довіри до власності.

## Складені дані та володіння

Вектори, рядки, структури — усе, що тримає інші значення, саме володіє ними. Коли ти переміщуєш вектор, переміщується і все, що він тримає (якщо воно не `Copy`). Це природно: володар вектору відповідає за свій склад.

```rust
fn total(v: Vec<i32>) -> i32 {
    v.iter().sum()
}

let numbers = vec![1, 2, 3];
let sum = total(numbers);
// numbers тепер недоступний
```

Знову переміщення, але тепер «з коробкою всередині». Ось порада: якщо функція любить вектор лише читати — нехай позичає `&[i32]` або `&Vec<i32>`. Тоді переміщення не буде, і ти зможеш користуватися вектором далі. Це рішення автора, а мова — лише чесна співрозмовниця.

## Коротко про `Copy` проти `Clone`

Ми вже сказали, що числа — `Copy`, а рядки — ні. Уточнимо словник: `Copy` означає «копіюється по бітах завжди», а `Clone` — «копіюється, але з явним викликом `.clone()`». Різниця у видимості.

```rust
let x = 5;
let y = x;      // Copy: без жодного виклику
let s = String::from("привіт");
let t = s.clone();  // Clone: явно проситься
```

`Copy` типи (числа, `bool`, `char`, масив із `Copy`-елементів) копіюються тихо, бо це дешево й безпечно. `Clone` типи (рядки, вектори) потребують явності, бо глибоке копіювання тяжче. Запам'ятай головне: переміщення — це передача володіння, `Copy` — це тихе копіювання, `Clone` — явне копіювання.

## Що відбувається зі старим значенням після переміщення

Часом цікаво, куди «дівається» попереднє значення після переміщення. Rust дозволяє використати стару змінну знову, але лише після *присвоєння нового значення*. До цього звертатися до неї — помилка.

```rust
let mut a = String::from("перший");
let b = a;          // a переміщено
a = String::from("другий");  // тепер a знову господар
println!("{a} {b}");
```

Тут переміщення «спорожнило» `a`. Коли ми даємо їй нове значення, `a` знову чинна. Суть не в «зникненні», а в *правах*: до нового присвоєння мова не дозволяє читати `a`, бо вважає, що старої домівки вже немає. Згодом ти навчишся відчувати цю «повторну заселеність» природно.

## Позички вкладені: коли позичка посилається на позичку

Можна позичити значення, яке вже позичене. Це не «позичка у позички» в юридичному сенсі, а просто ланцюг: `let r = &s; let r2 = &r;` — тут `r2` типу `&&String`. Деколи це трапляється автоматично, коли функція приймає `&str`, а ти маєш `&String`.

```rust
fn show(s: &str) { println!("{s}"); }

let name = String::from("зоря");
let ref_to_name = &name;
show(ref_to_name);  // компілятор сам «зігнув» &&String у &str
```

Таке «вирівнювання» позичок — звичайна робота компілятора. Твій код може бути простим, а мова сама веде позичку потрібною глибиною. Це ще один штрих турботи: не треба зайвої уяви про типи кожного шару.
