## Мова, яка пише саму себе

Існує різниця між тим, де ти пишеш ноти на папері, і тим, де ти програєш нотний текст. Перше — це дані, друге — виконання. А є ще третє чудо: правила, за якими ноти народжуються з простих жестів. У програмуванні цей третій рівень називається макросами: можливість навчити мову *породжувати* код із коротких форм.

Ти вже зустрічав макрос, навіть не помічаючи. `println!` і `vec!` — обидва зі знаком оклику — це макроси. Втім, їх використання було настільки природним, що вони не дивували.

## Що робить знак оклику

Знак оклику після імені говорить: «це не звичайна функція, а макрос». Макрос не отримує значення як функція, а обробляє *текст*, який ти пишеш, і перетворює його на інший текст — за правилами, які ти сам визначив.

Найчастіше зустрічається макрос `println!`. Він здається простою функцією, але макроси роблять те, чого функції не можуть: приймати різну кількість аргументів, розуміти форматування «на льоту», сприймати щось за значенням, а не обов'язково як вираз.

Ось перше враження:

```rust
fn main() {
    let x = 42;
    println!("Значення: {x}");
    println!("{}, {}, {}", 1, 2, 3);
}
```

`vec!` схожий: він дозволяє створити вектор із переліку, не вказуючи спосіб, як він росте:

```rust
let days = vec!["понеділок", "вівторок", "середа", "четвер", "п'ятниця"];
```

Спробуй зробити те саме через `Vec::new()` і п'ять `push` — і ти відчуєш, чому макрос зручніший. Знак оклику — це короткий запис для «розверни це, будь ласка».

## Міні-макрос власний

Створимо найпростіший власний макрос. Макроси будуються зі «зразків» (фонетично — `matcher`), у дужках — `$variable:type` кожен раз багаторазово:

```rust
macro_rules! three_times {
    ($expr:expr) => {
        {
            $expr;
            $expr;
            $expr;
        }
    };
}

fn main() {
    three_times!(println!("і знову"));
}
```

Цей макрос приймає довільний вираз `$expr:expr` і повторює його тричі. `macro_rules!` — це спосіб описати правило: «коли бачиш такий зразок — перетвори ось так». Це нагадує шаблон для листів: ти пишеш один шаблон, потім заповнюєш його щоразу новим ім'ям.

## Зірочка для повторень

Макрос сильніший, ніж просте «тричі», коли він уміє приймати багато повторюваних частин. Дивимось на `vec!` ближче — ось спрощена його дих:

```rust
macro_rules! my_vec {
    ($($item:expr),* $(,)?) => {
        {
            let mut temp = Vec::new();
            $(
                temp.push($item);
            )*
            temp
        }
    };
}

fn main() {
    let numbers = my_vec![1, 2, 3, 4];
    println!("{}", numbers.len());
}
```

У зразку ми маємо повторювану групу `$($item:expr),*` та `$(,)?` — можливо, кому наприкінці. Запис `)*` — це «повтори стільки разів, скільки в зразку було». Тіло макроса, що містить `$(temp.push($item);)*`, розмножується для кожного елемента. Ось і вся магія: шаблон із дикою карткою повторень.

## Чому макроси, а не функції

У тебе може виникнути справедливе питання: навіщо це, коли є функції? Відповідь у трьох словах: неможливі конструкції, гнучкість синтаксису, генерація.

Функція має типи повернення і фіксовану сигнатуру; макрос живе на рівні синтаксису і може породити все, що дозволено в мові. За допомогою макросів можна написати код, який повторює рутинну частину багато разів, створює функції з шаблонів, реалізовує доменні мови прямо в Rust.

Класичний приклад — цей рядок, який ти бачив у главі про структури:

```rust
#[derive(Debug, Clone)]
struct Firefly { flashes: u32 }
```

`#[derive(...)]` — це теж макрос-атрибут: він *породжує* реалізації трейтів з опису структури. Замість того щоб кожен раз вручну писати `impl Debug`, ми раз пишемо узагальнене правило, і мова наповнює його. Це яскраве обличчя макросів: вони зменшують кількість повторень, а отже — і шанс помилитися.

## Бути обережним із багатством

У макросах є підводні камені, і перед сном про них варто знати, щоб спати спокійно. Макрос змушує код писатися всередину його тексту з нуля: помилки в тілі макроса показуються якось незрозуміло. Інколи розгортання макроса буває спантеличним.

Тому спільнота дотримується правила: використовуй функції там, де можна, а макроси — там, де неможливо інакше. Макроси дають силу, а сила вимагає поваги. Зроби все простим спочатку.

## Зразки-фрагменти: зірки повторюються

Зразки макросів бувають не лише «вираз», а й багато інших категорій. Кожна категорія — окремий сорт фрагмента, який можна спіймати в патерні:

- `expr` — вираз;
- `ident` — ім'я (наприклад, назва змінної);
- `literal` — конкретне значення;
- `ty` — тип;
- `tt` — будь-який «токен-дерев» (майже все).

Уяви макрос, який створює змінну з ім'ям, яке ти передаєш:

```rust
macro_rules! make_name {
    ($name:ident) => {
        let $name = "зроблено макросом";
    };
}

fn main() {
    make_name!(evening);
    println!("{evening}");
}
```

Тут `$name:ident` — це «візьми будь-яке ім'я». Макрос створює змінну з цим ім'ям і кладе в неї рядок. Сила в тому, що ти вирішуєш, як зветься змінна, не вписуючи його жорстко — фрагменти гнучкі, як день.

Такі макроси виглядають чари, але насправді вони всього лише «мають шаблони», які мовний компілятор розгортає. Нехай спершу здається дивним: з часом відчуєш, що це та саме проста механіка, тільки трохи з іншого боку.

## Повторити: зірочка в дії

Зірочка в макросі — це «повтори стільки, скільки разів зустрілося». Погляньмо на звичайний макрос для «живого» переліку без форматування:

```rust
macro_rules! log_all {
    ($($x:expr),*) => {
        $(
            println!("рядок: {}", $x);
        )*
    };
}

fn main() {
    log_all!(1, 2, 3);
}
```

Після розгортання виходять три `println!` для чисел 1,2,3. Форма `$(*)...)*` — це зовнішній «розгін»: щоразу, коли знаходиться ще один елемент групи, тіло повторюється. Записуєш один раз, а виконується невизначена кількість. Це як поетичне повторення, яке народжує ритм.

## Макроси як міні-DSL

У тебе може виникнути питання: а навіщо так вигадувати, якщо можна з простою функцією? Звісно, можна! Але інколи макроси дають такий синтаксис, який функції не можуть: спеціальні «мови» міні-домену (DSL), які читаються як рідні речення.

Уявімо макрос для опису конфігурації:

```rust
macro_rules! config {
    ($name:ident => $value:expr) => {
        println!("параметр {name} = {value}", name = stringify!($name), value = $value);
    };
}

fn main() {
    config!(hours => 8);
    config!(silence => true);
}
```

`stringify!` усередині — ще один макрос: він перетворює ім'я-фрагмент у рядок. Завдяки цьому ти можеш говорити «параметр hours = 8», не думаючи про перетворення. Маленьке чаклунство, яке насправді чисто ділова механіка.

## Macros 2.0 і процедурні макроси

Світ макросів не закінчується `macro_rules!`. Є ще *процедурні макроси* — там макроси — це звичайні функції, які отримують токени і повертають токени. Вони писемніші в Rust-коді і зустрічаються у потужних бібліотеках: `serde` (серіалізація), `axum` (роутинг вебсервера) і багато інших використовують саме процедурні макроси.

Такі макроси позначаються як `#[proc_macro]`, `#[proc_macro_derive]` (для `#[derive(...)]`) або `#[proc_macro_attribute]` (для «атрибутів», на зразок `#[tokio::main]`). Це вже глибокий світ, і ми навіть не маємо наміру заходити в нього повністю. Головне — знати, що він існує і що з ним зустрічатимешся, коли крейт «робить магію» під час збірки.

## Коли слід утриматися від макросів

Чим більша сила, тим дужче запитання «а чи потрібна вона?». Перед сном запам'ятаємо три правильних застереження:

1. Якщо можна написати звичайну функцію і не мучитися — пиши функцію. Макрос ускладнює розуміння, тести та налагодження.
2. Макрос, який робить тіло «невидимим», — небезпечний: там, де код розгортається, помилки читатимуться з «макросного» боку. Тримай тіла простими.
3. Назви, кількість і повторення — природні кандидати для макросів. Складна логіка ухвалень — ні.

Ці три пункти — не заборони, а компас. Макрос — це міцний інструмент; уміти відкласти його — теж майстерність.

## Родина макросів у стандартній бібліотеці

Щоб ти відчув, що макроси — не рідкість, а частина повсякдення, згадаймо кількох членів родини зі стандартного арсеналу: `println!` і `print!` (друк), `vec!` (вектор), `format!` (форматування в рядок), `assert!`, `assert_eq!`, `assert_ne!` (перевірки), `panic!` (аварійна зупинка), `match!` (перевірка патерну), `todo!` і `unimplemented!` (заглушки). Усі вони — знайомці; тепер ти знаєш, яка спільна механіка за ними ховається.

Кожен із цих знаків оклику розгортається у звичайний код при збірці. І, що приємно, ти можеш читати ці макроси мови так само, як двері в домі: розуміти, куди вони ведуть, і не боятися зазирнути.

## Вправа на вечір

Спробуй з'єднати отримане: напиши макрос `repeat!`, який приймає вираз і лічильник, і повторює вираз потрібну кількість разів. Почни з простого: макрос із двома параметрами `($count:expr, $body:expr)`, а всередині — повторення через відомий тобі зразок. Це не завдання на чистоту коду, а вправа на відчуття «мова, яка розгортає».

Якщо захочеш складніший шлях — спробуй макрос, який створює одну змінну з іменем зі входу. Головне, щоб ти завершив вечір із відчуттям: у мову можна підправити, і стиль свого синтаксису — це теж спосіб сказати «цей код належить мені».

## Макроси, які створюють код із даних

Найпотужніше застосування макросів — генерація *патернів* із даних. Уяви макрос, який створює константний список із рядків:

```rust
macro_rules! map {
    ( $( $key:expr => $value:expr ),* ) => {
        {
            let mut m = std::collections::HashMap::new();
            $(
                m.insert($key, $value);
            )*
            m
        }
    };
}

fn main() {
    let cities = map!(
        "Київ" => 1,
        "Львів" => 2,
        "Одеса" => 3
    );
    println!("{}", cities["Київ"]);
}
```

Тут `$( ... ),*` повторює пару «ключ → значення» стільки разів, скільки передано. Один запис — і виникає ціла `HashMap`. Це крихітний приклад того, як макроси «пишуть код за тебе»: ти описуєш дані, а макрос будує структуру.

## Гігієна макросів

У макросів Rust є чудова якість — *гігієна*. Це означає: змінні, які створюються всередині макросу, не вступають у конфлікт зі змінними поза ним. Макрос не «виливає» свої тимчасові імена в навколишній код.

```rust
macro_rules! assign {
    ($x:ident, $v:expr) => {
        let $x = $v;
    };
}

fn main() {
    let temp = "зовнішнє";
    assign!(inner, 5);
    println!("{temp} {inner}"); // temp не перезаписано
}
```

`temp` ззовні й усередині — різні сутності. Макрос «облаштовує» своє тимчасове життя в окремій кімнаті. Це захищає тебе від дивних збігів імен — ще одна турбота Rust.

## Розгортання коду очима: `cargo expand`

Коли хочеш побачити, у що перетворюється твій макрос, Rust надає інструменти розгортання. Зовнішній `cargo expand` показує кінцевий код після дії всіх макросів. Це як зняти покривало і побачити механізм.

```text
cargo expand
```

Це не «чари», а можливість навчання: побачивши розгорнутий код, ти швидше зрозумієш, чому макрос поводиться так, а не інакше. Інколи «загадка» розв'язується за секунду.

## Небезпека надмірного використання

Маючи молоток, легко бачити цвяхи. Але не кожен фрагмент — макрос. Коли код *виглядає* шаблонним, але не повторюється — це просто код, і він не потребує макросу. Перевикористання макросів робить програму важкою для читання, налагодження та сумісності.

Питання-фільтр, яке варто ставити собі: «якби я мав написати це п'ять разів вручну — чи позбувся б я макросу?» Якщо так — макрос пробачний. Якщо ні — краще залишити код прозорим.

## `#[derive]`: макроси без тебе

Одне з найпоширеніших використань макросів настільки вбудоване, що його можна вважати окремою темою: `#[derive]`. Вона каже компілятору «згенеруй за мене стандартні методи». Це крихітна річ, яка щодня економить купу рядків.

```rust
#[derive(Debug, Clone)]
struct Point {
    x: i32,
    y: i32,
}
```

`Debug` дає зручний `{:?}`-друк, `Clone` — метод `clone`. Жодного рукописного коду — компілятор пише його за тебе з одного рядка. Це «запозичена магія» макросів, яку ти не мусиш розуміти детально, щоб користуватися щодня. Поруч із `Debug`/`Clone` часто зустрінеш `Copy`, `PartialEq`, `Eq`, `Hash` — вони теж `#[derive]`-генеровані або реалізовані самі.

## Композиція макросів: `format!` і `println!` пліч-о-пліч

Попри те, що `println!` друкує на екран, а `format!` повертає рядок, вони поділяють спільне «серце». Спробуй побачити їх як дві гілки одного дерева: одна бере відформатований рядок і виводить, інша бере його і віддає тобі.

```rust
let greeting = format!("Привіт, {}", "тебе");
println!("{greeting}");
```

Це композиція, а не «два різних механізми». Коли ти розумієш, що `format!` — це «рядок у руках», а `println!` — «рядок у світ», зв'язок стає прозорим. Не обов'язково читати їхній код; досить знати, що вони живуть з однієї родини.

## Макроси у виразах: тихе вкраплення

Макроси можуть входити туди, де ти їх не чекаєш, — як вирази всередині більших виразів. Такі вкраплення роблять код природнішим, бо «повтор» не розриває потік.

```rust
fn approx_len(s: &str) -> usize {
    s.len() + 2 // маленький «запас»
}

let name = "зоря";
let padded = format!("{}{}", approx_len(name), " !");
```

Це не макрос у строгому сенсі (тут звичайна функція), а нагадування, що Rust будує вирази з малих цеглинок. Уміння зібрати маленькі частини у велике — це не лише про макроси, а про загальний стиль виразно-орієнтованої мови. Макроси лише дають ще один спосіб такого «склеювання».

## Підсумок ночі про макроси

Ця глава дала тобі три ідеї, які варто забрати з собою в подальші ночі:

1. **Макроси — це інструмент швидкодії синтаксису**, а не загальна потреба. Вони живуть там, де повтор зовнішній і зрозумілий.
2. **Їхня сила — у гнучкості** (`expr`, `ident`, повтори), але ціна — у меншій явності.
3. **Найпростіше використання макросів уже біля тебе**: `println!`, `vec!`, `#[derive]` — ти ними користуєшся, навіть не думаючи.

З цими думками макросів нема чого боятися — і нема чого ними зловживати. Це баланс, до якого приходить більшість авторів із практикою.

## `concat!`, `cfg!`, `env!`: тихі макроси-помічники

Окрім друку та колекцій, стандартна бібліотека має кілька макросів, які «підказують» під час збірки. `concat!` з'єднує літерали, `cfg!` — перевіряє умови на етапі компіляції, `env!` — читає змінну середовища.

```rust
let version = concat!("версія ", "1.0");
println!("{version}"); // версія 1.0

// cfg! — прапорець «з якою системою»
if cfg!(windows) {
    println!("це Windows");
}
```

Такі макроси виконуються «наперед»: вони вже до запуску програми дають значення, які не зміняться. Це не магія, а «надійні літерали», які мають вигляд звичайного виразу. Їх корисно знати, бо часом вони рятують від громіздких умов.

## Зрозумілість атрибутів-макросів

Ми бачили `#[derive(Debug)]` і `#[cfg(...)]`. Такі дужки, що стоять перед елементом, називаються *атрибутами*. Для `cfg` компілятор уже вирішує, чи «вмикати» шматок коду, для `derive` — генерує методи. Це ще одна грань макросів: «мета» поверх звичайного коду.

Атрибути не «знаходяться» всередині функцій, а *обгортають* їх. Тому читання коду з атрибутами трохи інше: спершу подивися, що «женеть» над функцією, потім — усередині. З часом ти навчишся бачити атрибут як «етикетку», після якої йде саме тіло.

## Прямо зараз: маленька вправа з макросом

Щоб відчуття не згасло, зроби один дихальний крок: напиши макрос `greeting!`, який друкує «Спокійної ночі» з параметром імені. Використай `$name:expr` і `concat!` або просто `println!`.

```rust
macro_rules! greeting {
    ($name:expr) => {
        println!("Спокійної ночі, {}!", $name);
    };
}

fn main() {
    greeting!("вітре");
}
```

Це п'ять рядків, які показують, що макрос — це просто «чуйний шаблон». Не вимагай від себе більшого цього вечора: досить побачити, як приймати макроси спокійно.

## Магія `vec!`: що відбувається за знаком оклику

Увесь вечір ми говорили про макроси — і найкращий приклад уже живе в нас: `vec!`. Порівняй два способи зібрати вектор:

```rust
let mut a = Vec::new();
a.push(1);
a.push(2);
a.push(3);

let b = vec![1, 2, 3]; // набагато коротше
```

Макрос `vec!` — це «синтаксичне скорочення»: він розгортається в той самий код `Vec::new` + `push`, який ти бачиш зліва. Значення `vec!` не в новому слові, а в тому, що воно прибирає шум. Так і ти навчишся бачити за макросом його «довгу шпалеру» реального коду.

## Коли макрос не потрібен

Маємо й протилежне питання: коли *не варто* писати макрос? Почуте правило просте: якщо повторень мало (два-три) і вони ясні — залиши код просто копією. Макрос приносить щастя тоді, коли правил багато і вони складні.

```rust
// копіювання двічі — нормально
let x = add(1, 2);
let y = add(3, 4);
```

Виховуй міру: макрос — це не «красиве слово», а відповідь на реальну втому. Доки повторень небагато, простота перевершує економію. Уміння не вживати макрос — така сама майстерність, як і вміння його писати.

## Читання коду з макросами: мистецтво заглядання

Коли читаєш чужий код і бачиш загадковий макрос, не панікуй. Спосіб такий: спершу прочитай, *що* він робить за назвою та прикладом, потім — якщо сумніваєшся — знайди його визначення через пошук. Після цього повернися і запитай: «чи всі сенси я зрозумів?»

```text
# інструмент, який показує розгорнутий код макроса
cargo expand
```

`cargo expand` — це лупа: вона показує макрос уже «розгорненим» у звичайний Rust. Користуйся нею, коли хочеш точно знати, що невидимо. Так магія стає технікою, а ніч — спокійною.

## Медитація на ніч

Сьогодні ми побачили, що мова може сама себе переписувати: знайомий `println!` — макрос, `vec!` — макрос, `derive` — макрос. Ми навіть намалювали власний маленький зразок із повтореннями — і відчули, як за коротким знаком оклику ховається могутність.

Макроси навчають помічати структуру в рутинній боротьбі: коли бачиш, що один і той самий код повторюється тричі — це не просто втома, це запрошення для макроса. Перетворити повторення на правило — ось смак справжнього мистецтва.

> Мова вміє писати про саму себе.
> Короткий знак оклику —
> цілий згорток правил.
> Повторення народжує форму,
> форма — стиль,
> а стиль — це тиша, де раніше був шум.

До наступної глави. Добраніч.
