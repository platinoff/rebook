## Мистецтво розкладати по полицях

У дитинстві нас могла захопити гра: коли ти розкладаєш предмети по коробках, і кожен предмет має свою коробку, і ніщо не опиняється в чужій. Це заспокоює. `match` у Rust — саме така гра, тільки зі значеннями. Ти показуєш значення, і мова розкладає його по одній із коробок — по гілках — залежно від того, чим воно є.

## Перший match

Почнемо з простого. У нас є число години:

```rust
fn greeting(hour: u8) -> &'static str {
    match hour {
        0 | 1 | 2 | 3 | 4 | 5 => "Ніч ще триває",
        6 | 7 | 8 | 9 | 10 | 11 => "Ранок",
        12 | 13 | 14 | 15 | 16 | 17 => "День",
        _ => "Вечір",
    }
}
```

Зверни увагу на кілька речей. Рядок `0 | 1 | 2 ...` — це перелік значень, які належать до однієї гілки; вертикальна риска тут звучить як «або». А підкреслення `_` у останній гілці — це «будь-що, що не названо вище». Цей запис гарантує: які б числа ми не дали, відповідь знайдеться завжди. У `match` немає провалів у пітьму — кожен шлях має кінець.

`match` вимагає повноти: компілятор наполягає, щоб усі можливі варіанти були розглянуті. Якщо забудеш ніч — мова ввічливо нагадає. Це не суворість заради суворості: це спокій того, хто знає, що в кожній кімнаті світло вмикається.

## Коробки та їх вміст

`match` стає по-справжньому чарівним, коли ми відкриваємо коробки. Згадаємо `Option`: у ньому або `Some`, або `None`. Розбираємо:

```rust
fn describe(value: Option<u32>) -> String {
    match value {
        Some(n) => format!("є число {n}"),
        None => format!("порожньо"),
    }
}
```

У гілці `Some(n)` ми одразу дістаємо значення зсередини. Це не папірець, який треба спершу відкривати окремою дією: `match` робить це за один крок. Такий спосіб називається *розкладанням* (destructuring) — і він працює не тільки з `Option`, а з будь-якими складеними формами.

## Структури розкладаємо теж

Припустимо, у нас є структура — опис нічного неба:

```rust
struct Sky {
    stars: u32,
    moon: bool,
}

fn mood(sky: Sky) -> String {
    match sky {
        Sky { stars: 0, moon: false } => "цілковита темрява".to_string(),
        Sky { stars, moon: false } => format!("чисте небо без місяця, зірок: {stars}"),
        Sky { stars: s, moon: true } if s > 100 => "небо багате, місяць світить".to_string(),
        Sky { moon: true, .. } => "місяць панує, зірки скромні".to_string(),
    }
}
```

Тут видно дві тонкі деталі. Перша: `..` говорить «решту полів пропусти — вони не важливі для цієї гілки». Друга: рядок `if s > 100` — це *охорона* (guard): гілка спрацьовує лише за умови. Охорона — це як дружній дотик до плеча: «почекай-но, перевірмо ще одну річ, перш ніж ухвалити рішення».

## Міцно і без падінь

Розглядаючи масиви або зрізи, `match` дає витончену безпеку. Спроба взяти елемент за індексом, якого немає, — це класичне джерело страху в багатьох мовах. Rust заспокоює тим, що індексацію можна обережно оповити:

```rust
let items = [10, 20, 30];

match items.get(5) {
    Some(value) => println!("знайшов: {value}"),
    None => println!("такого місця немає — і це теж добре"),
}
```

`get` повертає `Option`: замість того щоб упасти, код спокійно повідомляє «такого місця немає». Це не помилка, це стан речей. Програма не розвалюється, а дивиться на світ чесно.

## `if let` — коли коробка одна

Інколи чуєш: «мені важлива лише одна гілка». У таких випадках повний `match` виглядає величним, але громіздким. Rust дає коротку форму — `if let`:

```rust
let door = maybe_key();

if let Some(key) = door {
    println!("є ключ із цифрою {key}");
} else {
    println!("замок чекає, ключа поки що немає");
}
```

Це той самий `match`, тільки з однією гілкою та спільним «інакше». Хтось скаже «скорочення», а я скажу «ввічливість». Інколи досить сказати одне слово, а не розсипатися в усіх можливостях одразу.

## Патерни як мова опису форм

Тепер подивись на все це з висоти птаха. `match`, `if let`, `Some(n)`, `Sky { stars, .. }`, `_` — це не окремі дрібниці. Це *мова патернів*: вона дозволяє описати форму того, що ми очікуємо побачити, і назвати частини, які потрібні. Компілятор звіряє цю мову з реальністю і каже, чи все враховано.

Ця мова — вірний сторож твоєї ночі: вона не дозволяє одній із дверей лишитися незачиненою. У `match` не буває «а що, як значення зовсім інше?» — бо або є гілка `_`, або всі варіанти перелічені. Мовчазних отворів немає.

## Погляд без дзеркала

Перед тим як завершити, зробимо одне з'єднання: патерни — це спосіб мови розмовляти про те, що може бути, — а не про те, що точно є. `Option` говорить «може бути, а може й не бути», `Result` — «може бути успіх, а може — пояснення», строки — «може бути кілька годин». Патерни навчають мислити станами, а не просто значеннями.

Мислити станами — це мислити спокійно, бо ти вже розкладаєш світ по полицях, перш ніж він тобі що-небудь кине.

## Гілки народжують значення

У главі про вирази ми побачили, що `if` уміє повертати значення. `match` теж має цей дар, і він навіть могутніше: кожна гілка — окрема будова значення, і всі мають бути одного типу.

```rust
let phase = match hour {
    0 | 1 | 2 | 3 | 4 | 5 | 6 => "світанок ще далеко",
    7..=11 => "ранок",
    12..=17 => "день",
    _ => "вечір",
};
println!("зараз {phase}");
```

Поглянь на нове: `7..=11` — діапазон значень. Це ще один патерн, який говорить «числа від семи до одинадцяти включно». Патернів у мови багато: точні значення, діапазони, «або» через `|`, значення всередині коробок — і всі вони зручно складаються в одну розповідь.

Різниця від `if` лише в одному: `if` перевіряє умову, а `match` — *форму*. Ми питаємо не «чи правда?», а «на що це схоже?». Звучить схоже, а відчуття — інше: ми не ставимо запитань, ми впізнаємо обличчя.

## Розкладання кортежів і структур

Патерни вміють розбирати на частини практично будь-яку структуру. Кортежі — як маленькі пакунки:

```rust
let point = (3, 7);
let (x, y) = point;
let (a, b) = match point {
    (x, y) if x < y => (y, x),
    (x, y) => (x, y),
};
```

Тут, крім простого розкладання, ми бачимо охорону `if x < y` у праві гілці: спершу зіставлення форми, потім перевірка умови. Це два різні рівні дозволу: спочатку зовнішній вигляд, потім внутрішня правда. Коду стає зрозуміліше, куди мова тече, а тим — спокійніше.

## `match` як водій повернення

Часто `match` стоїть останнім рядком функції — і тоді функція «повертає все, що знайшла»:

```rust
fn describe_sky(stars: u32) -> String {
    match stars {
        0 => "беззоряна ніч".to_string(),
        1..=9 => "скромне небо".to_string(),
        10..=99 => "багате небо".to_string(),
        _ => "вражаюча пишнота".to_string(),
    }
}
```

Тут у `match` повертаються `String`, і вони стають результатом функції. Це ще один зразок виразно-орієнтованого стилю: опис будується одним виразом, без безлічі `return` і тимчасових змінних.

## Коли `match` не потрібен

З тією самою обережністю скажемо, що `match` — не завжди найкращий інструмент. Якщо тобі потрібна лише одна гілка та «інакше» — `if let` або `let else` можуть бути чистішими:

```rust
let maybe = Some(5);

if let Some(v) = maybe {
    println!("маємо {v}");
} else {
    println!("порожньо");
}
```

Це коротко й зрозуміло: «якщо це Some — дістань і покажи; інакше — поспівчувай». Для однієї гілки він легший за перевірку `match`, яка вимагало б зайвих рядків. Вибір — питання смаку, а гарний смак приходить із практикою.

## Повнота як добробут

Найбільш постійне враження, яке залишає `match`, — повнота. Компілятор не дасть забути гілку: для `bool` — лише `true/false`, для `Option` — `Some/None`, для власних переліків — усі варіанти. Це не примха, а гарантія: код не «мовчиться» про можливості.

У великих програмах ця звичка рятує життя. Додав новий варіант у перелік — компілятор одразу покаже всі місця, де цей варіант не врахований. Ти не забуваєш «розглянути» нового гостя — мова про нього пам'ятає краще за тебе.

## Вправа на сьогодні

Спробуй описати свій вечір як розгалуження: візьми кілька фактів (час доби, настрій, місце) і склади `match`, який обирає відповідне привітання. Небо — палітра: спокій, активність, пізня втома. Повправся з діапазонами та охоронами.

Не обов'язково запускати код. Досить «проговорити» патерн уголос: «якщо час з 17 до 21 — вечірня тиша; якщо з 21 і далі — готуйся спати; охорона: якщо втома велика — одразу ліжко». Ти вже навчаєш мозок бачити цей самий патерн у Rust, лише під свіжою формою.

## Глибша гра: match і переліки як цілісні моделі

Переліки з даними — це не «множинний вибір»; це спосіб описати *всі можливі стани* і мати гарантію, що жоден не пропущений. Коли ти пишеш `match`, компілятор перевіряє: якщо ти обробив усі гілки — жоден сюрприз не зможе пройти. Якщо забув — він скаже, де саме.

Це як карта метро: є станція А, Б, В. Якщо ти з'єднав усі три переходи — потяг їздить. Якщо один перехід забули — компілятор скаже «тут незавершений маршрут». Ось чому `match` — не просто перевірка, а *модель* стани світу.

## Match як функція

`match` може повертати значення — і це часто зручніше за `if-else`. Замість того щоб писати «якщо так — поверни одне, інакше — інше», ми просто кажемо «ось усі можливості, ось результати»:

```rust
fn describe(day: &str) -> &'static str {
    match day {
        "понеділок" => "початок тижня",
        "п'ятниця" => "майже вихідні",
        _ => "звичайний день",
    }
}

fn main() {
    println!("{}", describe("понеділок"));
}
```

Тут `match` — це вираз, який повертає рядок. Ніяких `return`, ніяких додаткових змінних. Один запис, і результат народжується прямо там, де ти його чекаєш. Елегантність, яка не потребує коментарів.

## When not needed: де обходяться без match

Є ситуації, де `match` занадто важкий. Якщо ти просто перевіряєш одне значення на рівність — `if let` коротший:

```rust
fn main() {
    let config_value = Some(42);

    if let Some(v) = config_value {
        println!("{v}");
    }
}
```

`if let` — це «м'який match»: він каже «якщо є цей варіант — зроби щось, інакше — не хвилюйся». Це не заміна `match`, а дружній сусід, який з'являється тоді, коли тобі не потрібна повна карта.

## Повнота і неможливість

Rust не дозволяє «забути» гілку. Якщо ти перерахував три варіанти переліку, а четвертий залишив без обробки — компілятор скаже «тут незавершено». Це не настирливість; це *захист*: жоден випадок не випадає з уваги.

Єдиний виняток — гілка `_ => ...` (або `other => ...`), яка каже «все, що залишилося — ось так». Але навіть вона — свідомий вибір, а не забуття. Компілятор знає, що ти взяв на себе відповідальність за «решту світу».

## Вправа на вечір

Опиши собі функцію, яка приймає перелік `Season` (весна, літо, осінь, зима) і повертає рядок із «настроєм». Спробуй зробити так, щоб жодна гілка не була «порожньою» — і компілятор був задоволений. Потім спробуй додати п'ятий сезон — і подивись, що скаже компілятор. Це чудовий спосіб відчути, як «підказки» перетворюються на стінограму коду.

## Вкладені `match`: коробки у коробках

Інколи значення лежить усередині іншого значення, і тобі треба розібрати обидва шари. `match` можна вкладати один в одного — ти розкладаєш зовнішню коробку, а потім, у середині гілки, розкладаєш внутрішню.

```rust
fn unpack(x: Option<Option<i32>>) -> String {
    match x {
        Some(Some(v)) => format!("подвійно: {v}"),
        Some(None) => "зовнішня є, внутрішня порожня".into(),
        None => "зовнішньої немає".into(),
    }
}
```

Два шари `Option` — два рівні питання: «чи є зовнішній? чи є внутрішній?». Rust дозволяє відповісти на обидва одразу. Не зловживай вкладенням (занадто глибке вже важко читати), але знати, що воно можливе, — потрібно.

## Зв'язування `@`: дати ім'я зіставленому

Часом ти хочеш одночасно перевірити, чи значення збігається з шаблоном, — і ще дістати його за ім'ям. Rust має оператор `@`, який «зв'язує» значення з ім'ям у межах зіставлення.

```rust
fn describe(n: u32) -> String {
    match n {
        0 => "немає".into(),
        small @ 1..=9 => format!("мале: {small}"),
        other => format!("велике: {other}"),
    }
}
```

Тут `small @ 1..=9` означає «якщо число в межах — запам'ятай під ім'ям `small`». Це зручно, коли за шаблоном мовчить значення, до якого хочеш звернутися. `@` — маленький, але частий гість у дорослому коді.

## Патерн `..`: пропусти все інше

У структурах та кортежах буває багато полів, але цікавлять лише кілька. Патерн `..` каже «решта неважлива, пропусти»:

```rust
struct Portrait {
    name: String,
    width: u32,
    height: u32,
}

fn is_portrait(p: Portrait) -> bool {
    match p {
        Portrait { height, .. } if height > 100 => true,
        _ => false,
    }
}
```

Тут ми дістаємо лише `height`, а решту полів «пропускаємо трьома крапками». Це тримає код коротким, коли структура багатопільна. Rust вимагає лише назвати ті поля, які ти дійсно хочеш використати, — `..` бере на себе решту.

## `let else`: коробка або вихід

Раніше ми бачили `if let`. Його близький родич — `let ... else`: він каже «якщо це розкладається ось так — продовжуй; інакше — вийди з функції».

```rust
fn first_code(value: Option<u32>) -> u32 {
    let Some(n) = value else {
        return 0;
    };
    n * 10
}
```

Тут `let Some(n) = ... else` дістає значення з коробки; якщо його нема — одразу завершує функцію запасним значенням. Такі конструкції тримають код прямим: немає довгих `match` тоді, коли ти просто прагнеш «дістати або піти».

## `match` над посиланнями

Цікава особливість: `match` працює й над посиланнями. Коли ти маєш `&Option<T>` і зіставляєш, Rust «розуміє», що гілки бачать посилання — тобто не забирають володіння.

```rust
fn emoji(opt: &Option<String>) -> &str {
    match opt {
        Some(_) => "є 🌙",
        None => "немає",
    }
}
```

Тут усередині ми не беремо володіння рядком; ми лише дивимось, яка гілка. Це чесне читання, не переміщення. Такі патерни трапляються щодня, коли функції приймають `&Option` або `&Result` — і Rust дозволяє описувати це без зайвого клону.

## Патерн-охорона у власних переліках

Ми вже бачили охорону (`if` всередині гілки) на простому прикладі. Тепер подивимось, як вона оживає у власних переліках із даними:

```rust
enum Drink {
    Tea { spoons: u8 },
}

fn strength(d: Drink) -> &'static str {
    match d {
        Drink::Tea { spoons } if spoons >= 3 => "міцний",
        Drink::Tea { spoons } => "легкий",
    }
}
```

Тут охорона `if spoons >= 3` вирішує між двома гілками одного й того ж варіанта. Це чисте рішення: спершу форма, потім значення. Охорона додає гнучкість, коли одного зіставлення недостатньо.

## `if let` як двері без повного `match`

Коли нам треба лише «подивитися, чи є значення», повний `match` може здатися громіздким. Сюди приходить `if let`: коротка перевірка одного варіанта.

```rust
let maybe = Some(7);
if let Some(n) = maybe {
    println!("число: {n}");
}
```

Тут нічого не «губиться»: якщо `maybe` — `None`, ми просто тихо минаємо блок. `if let` — це та сама сортування, але для однієї коробки: відкрив, переконався, попрацював. Це не спрощення заради ліні, а виразність для ясної мети.

## `let ... else`: короткий вихід із функції

Близький родич `if let` — форма `let ... else`. Вона каже: «якщо розкладається — вбери; якщо ні — повернися з функції». Це унікальний спосіб «дістати або піти».

```rust
fn parse_port(text: &str) -> u16 {
    let Some(p) = text.parse().ok() else {
        return 0;
    };
    p
}
```

Тут якщо рядок не число — повертаємо 0, інакше — значення. Це стиснутий і прямий почерк, без зайвих `match`. Коли логіка «спершу перевір, чи можна продовжити» — ця форма стає другом, а не хитрістю.

## Патерни в `match` над числами

Ми вже зіставляли типи, а тепер глянемо на дробову частину: `match` над числами дозволяє обирати за діапазонами через `..=`.

```rust
fn opis(v: u8) -> &'static str {
    match v {
        0 => "нічого",
        1..=3 => "мало",
        4..=10 => "достатньо",
        _ => "багато",
    }
}
```

Діапазон `..=` включає обидві межі. Це природний спосіб описати числові категорії без довгих ланцюжків `if`. Число — така сама річ для зіставлення, як і структура; `match` уміє сортувати і їх, даючи чисті відповіді.

## Медитація на ніч

Сьогодні ми розкладали значення по коробках, відкривали `Option`, розбирали структури, охороняли гілки умовами й користувалися скороченою формою `if let`. Навчилися, що у `match` немає провалів: кожна річ потрапляє в свою коробку, і коробок достатньо для всіх.

Не вчи напам'ять синтаксис. Відчуй образ: сортування, де жоден предмет не загублений, де кожен вміст на своєму місці, і полиця знає, що на ній живе.

> У кожної гілки — своя коробка,
> а порожньому місцю — своя,
> яке б значення не зазирнуло в двері —
> воно знайде свій дім.
> Мовчазних отворів не лишає Rust.
