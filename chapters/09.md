## Багато предметів поряд

Досі ми мали справу з одним значенням угорі. Але життя — це безліч речей: список справ, колекція зірок, словник назв. Rust дає для цього колекції — контейнери, які вміють тримати багато значень й упорядковувати їх так, як ми хочемо.

Сьогоднішня глава — про три найважливіші контейнери: вектор (`Vec`), словник (`HashMap`) і множину (`HashSet`). А також про одну найбільшу здатність, яка проходить крізь них усі, — ітератори.

## Вектор — коробка, що росте

`Vec` — це, грубо, коробка, яка вміє рости за потреби. Туди можна додавати, звідти можна читати:

```rust
let mut evenings = Vec::new();
evenings.push("понеділок");
evenings.push("вівторок");
evenings.push("середа");

println!("{}", evenings.len());          // 3
println!("{}", evenings[0]);             // "понеділок"
```

Читати через індекс зручно, але небезпечно, якщо індекс загубився. Тому краще — так само, як ми робили з `get` у главі про патерни:

```rust
match evenings.get(7) {
    Some(day) => println!("{day}"),
    None => println!("такого дня в коробці немає"),
}
```

`Vec` — це коробка, у якій зручно тримати порядок і яка дозволяє рости, коли ти поклав ще. Нею легко користуватися, і вона дружелюбна до ітерацій.

## Перебір без рук

Найдопитливіша здатність колекцій — це вміння перелічувати себе. Це називається ітерацією, і в Rust вона виражається рідним циклом:

```rust
for day in &evenings {
    println!("Вечір: {day}");
}
```

Цикл `for` тут не відокремлений від колекцій: він, по суті, просить колекцію «дай мені кожен елемент по черзі». `&evenings` — позичення, тож ми перебираємо, не забираючи коробку. Чудова річ: компілятор сам не дасть змінити вектор, поки ми по ньому йдемо — це як не писати в книзі під час читання.

## Ланцюги перетворень

Ітератор — це не лише цикл. Це са́ме те, на чому можна робити ланцюжок перетворень: кожен крок бере поточний перебір і віддає новий. Результат читається як розповідь:

```rust
let squares: Vec<u32> = (1..=5)
    .map(|n| n * n)
    .filter(|n| n % 2 == 1)
    .collect();
```

Що тут сталося: числа від 1 до 5 включно, кожне піднесено в квадрат (`map`), лишили непарні (`filter`), результат зібрано у вектор (`collect`). Вийшло `[1, 9, 25]`. Кожен крок — простий і зрозумілий; разом вони — маленька історія. Коду стають менш навантаженими на змінні-середини: не треба тримати п'ять тимчасових значень, усе тече між руки.

## Різні смаки перебирання

Ітератори бувають по-різному щедрі. `iter()` позичає елементи, `.into_iter()` забирає їх із собою (вони належатимуть результату), `.iter_mut()` дозволяє змінювати елементи на ходу. Поглянь на три обличчя:

```rust
for x in vec.iter()       { }  // читаю, нічого не беру
for x in vec.iter_mut()   { *x += 1; }  // читаю і правлю
for x in vec             { }  // забираю саму коробку
```

Ті, хто приходить «почитати», не порушують власність. Ті, хто приходить «поправити», потребують, щоб ніхто інший не дивився. А того, хто забирає коробку, більше не бачать у попередньому домі — вона переїхала. Це та сама мова власності, яку ми вивчили раніше, тепер просто застосована до багатох елементів.

## Словник — книга відповідей

`HashMap` — це словник: він впорядковує пари «ключ — значення». Якщо ти шукаєш, скільки зірок у сузір'ї на його ім'я — це робота для словника:

```rust
use std::collections::HashMap;

let mut constellations = HashMap::new();
constellations.insert("Оріон", 7);
constellations.insert("Велика Ведмедиця", 7);
constellations.insert("Кассіопея", 5);

match constellations.get("Оріон") {
    Some(count) => println!("{count}"),
    None => println!("не знайдено сузір'я"),
}
```

Словник жадібний до ключів: пошук швидкий, і ти отримуєш `Option` — або є значення, або його нема. Користуючись ним, зручно лічити, скільки разів трапився той чи інший предмет:

```rust
let mut counts = HashMap::new();
for w in "тиша тиша спокій".split(' ') {
    *counts.entry(w).or_insert(0) += 1;
}
// counts: {"тиша": 2, "спокій": 1}
```

Рядок `entry(w).or_insert(0)` — це розумний хідник: «візьми місце під ключ w, якщо його нема — створи з нулем». Так ми в один дотик оновлюємо лічильник, не тягаючи словник туди-сюди.

## Множина — колекція унікальностей

`HashSet` — це словник, який пам'ятає лише ключі: він зберігає кожен елемент рівно один раз. Додавання вдруге нічого не змінює. Це зручно, коли потрібно знати «Чи був уже такий вечір?»

```rust
use std::collections::HashSet;

let mut visited = HashSet::new();
visited.insert("Київ");
visited.insert("Львів");
visited.insert("Київ");

println!("{}", visited.len()); // 2 — Київ не дублюється
```

Множина — це як записник із пам'яттю: він не любить повторень. Якщо щось уже записане, запис знову — це лише нагадування, а не нова строчка.

## Уникаємо порожньої паніки

Часом ми потрібні коробці, яка вміє зменшуватися: виймати найменше, найбільше, або конкретне значення. `Vec` уміє бути чергою:

```rust
let mut stack = vec![1, 2, 3];
let top = stack.pop();   // Some(3)
let first = stack.first(); // Some(&1)
```

`pop` повертає `Option` — бо порожня коробка не має верхнього елемента. Так само `get`, `first`, `last` — усе повертає коробки з відповіддю. Ми вже навчились поводитися з ними спокійно: або є, або ні, і ніде немає несподіваного падіння.

## Вектори: керування ростом

Ми вже знаємо, що `Vec` — коробка, яка росте. Тепер розглянемо, як вона це робить, адже розуміння росту допомагає писати швидкі й передбачувані програми. Коли вектору бракує місця, він не додає один елемент — він «переселяється» у нову більшу коробку й копіює все вмістище. Такі переселення рідкі, але коштують; тому часто одразу резервують простір:

```rust
let mut evenings = Vec::with_capacity(7);
println!("день, ще нема елементів, але місце зарезервовано");
```

`with_capacity(7)` каже: «приготуй місце для семи, а елементи ще можна додавати». Звичайно, ти не мусиш це робити завжди, але коли наперед знаєш, скільки елементів буде — це рятує зайві переселення. Скромна звичка, що береже час.

## Способи створити вектор

Вектор можна створити багатьма способами, і вони підказуються самим кодом. Поруч із `vec!['...']` і `Vec::new()` — розмаїття:

```rust
let a = vec![1, 2, 3];
let b: Vec<i32> = Vec::new();
let c = Vec::from([1, 2, 3]);
let d: Vec<i32> = (1..=5).collect();
let e = vec![0; 4]; // чотири нулі
```

Зверни увагу на `vec![0; 4]`: повторення значення `0` чотири рази. А `(1..=5).collect()` — це «збери діапазон у вектор», про ітератори ми говоримо далі в цій главі. Різноманіття не для заучування — просто знай, що вектор ручний: для кожного наміру є зручний стілець.

## Читання за індексами, безпечно

Класичні запитання індексації ми вже торкалися. Погляньмо тепер два способи «взяти елемент» — прямий і обережний:

```rust
let items = vec![10, 20, 30];

let a = items[0];              // 10; пряме звертання
let maybe = items.get(1);      // Some(&20); обережне
let none = items.get(9);       // None; поза межами
```

`items[0]` вимагає, щоб індекс точно існував, а якщо ні — паніка. `get` ніколи не панікує: він повертає `Option`. У коді, який піклується про спокій, частіше бачить `get` — особливо коли індекс прийшов іззовні. Різниця в стилі дороги: одна — вулиця без питань, друга — вулиця з радаром.

## HashMap: куди швидко шукати

Словник уже з'явився в нас у главі; тут — дві звички, які роблять його використання мирним. Перша — `entry`, який не дублює коди записів:

```rust
use std::collections::HashMap;

let mut storage = HashMap::new();
*storage.entry("ключ").or_insert(0) += 1;
```

`entry` повертає або місце зі старим значенням, або місце щойно створене. `or_insert(0)` каже: «якщо нема — поклади нуль». Разом — ідеальне оновлення лічильника, без ідіотичного «спершу перевір, потім встав».

Друга звичка — перебирати пари:

```rust
for (key, value) in &storage {
    println!("{key} => {value}");
}
```

Словник перебирається парами «ключ → значення», і це приємно читається. Не забувай лише, що порядок у словнику не гарантований: він не «черга», а «книга, впорядкована за правилами хешування», тож не розраховуй на конкретний порядок — він може бути іншим при кожному запуску.

## Множини в дії

`HashSet` ми бачили як «колекцію унікальностей». Тепер подивимось, чим вона жива на практиці: перевірка приналежності, перетин, об'єднання:

```rust
use std::collections::HashSet;

let week : HashSet<&str> = ["пн","вт","ср","чт","пт"].iter().copied().collect();
let free : HashSet<&str> = ["пн","ср","пт"].iter().copied().collect();

println!("{}", week.contains("вт"));   // true
for day in week.intersection(&free) {
    println!("спільний день: {day}");
}
```

`contains` — питання «чи є?», `intersection` — «що в обох?». Множини особливо сильні там, де треба порівнювати «наявність» без дублювань. Якщо програма постійно питає «чи вже бачив?» — множина прямо для цього.

## Ланцюги ітераторів: глибше

Ми вже складали ланцюг `map` → `filter` → `collect`. Погляньмо, наскільки виразнішими можуть бути ці ланцюги, коли додаються свої ланки. Приклад — вибрати дні тижня, які є «робочими», перетворити на великі літери й зібрати в рядок:

```rust
let week = ["пн", "вт", "ср", "чт", "пт", "сб", "нд"];
let busy = week
    .iter()
    .filter(|d| **d != "сб" && **d != "нд")
    .map(|d| d.to_uppercase())
    .collect::<Vec<_>>();
```

Рядок за рядком, крок за кроком: перебір, фільтр, перетворення, збирання. Кожен крок — окрема ланка, яку можна читати як речення англійською, тільки програмуванням. І всі ці ланки не створюють зайвих тимчасових колекцій — ітератор ліниво тягне дані.

## Лінивість: краса і турбота

Важливе слово про ітератори: вони *ліниві*. Поки ти не «викликав» результат (не зібрав через `collect`, не прогнав через цикл), нічого не виконується. Це не ганьба, а перевага: ти будуєш опис, а виконання відбувається рівно один раз, у потрібній формі.

Лінивість дозволяє безпечно об'єднувати незліченні перетворення, написати читання з «безкінечних» джерел і не турбуватися про зайві копії. Як хвиля, що тече, нічого не несучи на берег, поки ти не попросив.

## Вправа на вечір

Склади свою колекцію «вечірніх звичок»: вектор рядків, де кожна звичка — це слово (наприклад, «читати», «чай», «тиша»). Використай `contains`, щоб дізнатися, чи є «тиша» у твоєму списку. Порахуй елементи через `.len()`. Перебери весь список циклом `for`.

Це не завдання, яке перевіряється, — це прогулянка. Мета — відчути, як вектор природно входить у руку. Коли навчишся тримати його міцно, решта колекцій стане лише справою моменту.

## Лінивість ітерації: push, вибір, перетворення

Ітератори — це не лише «цикли». Вони — конвеєр, який пропускає дані через *безліч* малих операцій, а результат збирає в кінці. Це називається *лінива* (lazy) поведінка: жодне перетворення не відбувається, доки ти не «забереш» результат.

```rust
fn main() {
    let numbers = vec![1, 2, 3, 4, 5, 6];
    let evens: Vec<i32> = numbers
        .iter()
        .filter(|&&n| n % 2 == 0)
        .map(|&n| n * 10)
        .collect();
    println!("{evens:?}"); // [20, 40, 60]
}
```

`filter` відбирає, `map` перетворює, `collect` збирає. Кожна з цих операцій — як сходинка на шляху; жодна не виконується, поки кінцевий `collect` не «прозвучить». Це потужно, бо ти можеш з'єднувати будь-яку кількість кроків, і дані не копіюються проміжно.

## Ланцюжки без кінця: продуктивна краса

Інколи ланцюжки ітерацій стають довгими. І це нормально: вони і є спосіб описати обробку даних *декларативно*, наче ти кажеш «ось все, що має статися», а не «зроби крок за кроком».

Спробуй прочитати наступний ланцюжок як речення: «взяти числа, відібрати ті, що більші за три, дати лише перші п'ять, подвоїти їх і зібрати в список». Це і є декларативний стиль — мова замість команд.

```rust
let result: Vec<i32> = (1..=100)
    .filter(|n| n > 3)
    .take(5)
    .map(|n| n * 2)
    .collect();
```

Не бійся довгих ланцюжків; бійся лише такого ланцюжка, який не можна прочитати. Якщо кожна ланка ясна — ланцюжок гарний.

## Range: діапазони як нескінченність

`(1..=100)` — це діапазон від 1 до 100 включно. `..` — виключно, `..=` — включно, `..` без початку чи кінця — відкритий у потрібний бік. Діапазони — це «породжувачі» числових послідовностей, які поєднуються з ітераторами і створюють чисту, безкінечну уяву.

## Ітерація по рядках з файлу

Вектори і ланцюжки не лише про числа. Погляньмо, як приємно обробляти рядки файлу разом з ітераторами:

```rust
fn main() {
    let text = "рядок один\nрядок два\nрядок три";

    for line in text.lines().enumerate() {
        let (idx, content) = line;
        println!("{}. {content}", idx + 1);
    }
}
```

`lines()` — розбиває на рядки, `enumerate()` — додає номери. Комбінація цих маленьких кроків — це спосіб описати цілий «обід» обробки простими, зрозумілими реченнями. Це не магія; це природний стан Rust-розробника.

## Вправа на вечір

Справжня, хоча й тиха, вправа: напиши функцію, яка приймає `&[i32]` і повертає суму квадратів лише *позитивних* чисел. Використай ланцюжок: `filter` (позитивні), `map` (квадрати), `sum` (сума). Це одномінутна робота коду і десятихвилинне задоволення від стилю.

## `Vec`-методи, які ми ще не згадували

Вектори мають більше методів, ніж ми бачили: `resize` (заповнити відповідну довжину), `retain` (лишити лише за умовою), `dedup` (прибрати сусідні дублікати), `reverse` (перевернути). Не всі потрібні щодня, але зручно знати, що вони існують: коли прийде потреба, вони вже в пам'яті.

```rust
let mut nums = vec![1, 2, 2, 3, 3, 3];
nums.dedup();      // [1, 2, 3] — сусідні однакові згорнуто
nums.reverse();    // [3, 2, 1]
println!("{nums:?}");
```

Ці методи не роблять магії — вони просто втілюють найчастіші запити до колекції, щоб тобі не переписувати цикл щоразу. Знайомство з `Vec`-родиною — це як каталог дому: чим більше знаєш, тим рідше «відкриваєш забуті шафки».

## `HashMap`-методи для швидкого вибору

Уже згадували `entry`, але є ще пари зручних методів: `contains`-перевірка (`contains_key`), оновлення лише тоді, коли ключ існує, пошук зі значенням за замовчуванням (`get` + `unwrap_or`). Деякі з них ми бачили в дії. Додамо відтінок: перевіряти, чи ключ існує, до «вставки», — це звичайний танець:

```rust
let mut map: HashMap<String, u32> = HashMap::new();

if !map.contains_key("зоря") {
    map.insert("зоря".to_string(), 1);
}
```

Зауваж: цієї перевірки можна уникнути через `entry`, але прямий `contains_key` читається природно для тих, хто тільки звикає. Обидва шляхи валідні; обирай той, що зрозуміліший тобі в даний момент, а з часом `entry` стане другом.

## Колекції та дозволені межі

Як і вектори, `HashMap` і `HashSet` дозволяють лише ті ключі, які мають `Hash` та `Eq`. Це не обмеження заради обмеження, а вимога механізму: щоб швидко знайти елемент, мова має вміти перетворити ключ у число та порівняти за рівністю. Більшість базових типів (числа, рядки) вже мають ці трейти.

А якщо твій власний тип хоче бути ключем — ти можеш сам реалізувати `Hash` і `Eq` (або просто використати `#[derive(Hash, Eq, PartialEq)]`). Не соромся колекцій, вони — добрі товариші, а правила входу читаються в одну секунду.

## Ітерація та її порядок у словнику

Важлива деталь, яку повторюють усі: *порядок ітерації у `HashMap` не визначений*. Це означає, що ти не можеш розраховувати на «перший» чи «останній» ключ. Якщо тобі потрібен стабільний порядок — скористайся `BTreeMap` (вона тримає ключі відсортованими) або відсортуй ключі сам.

```rust
let mut h = std::collections::HashMap::new();
h.insert("а", 1);
h.insert("б", 2);
for (k, v) in &h { println!("{k}: {v}"); } // порядок — довільний
```

Тут порядок друку може змінюватися між запусками. Для діагностики це норм, для «розмови з виведенням» — ні. Колекція — не зобов'язання, а інструмент; опануй ту, що пасує до твоєї задачі.

## `Vec` проти `HashMap`: невеличкий путівник вибору

Коли обираєш між вектором і словником, постав два запитання: *чи потрібен мені «впорядкований список»?* та *чи шукатиму я за ключем*? Відповіді ведуть у правильний бік:

- **`Vec`** — коли важливий порядок і всі елементи важливі.
- **`HashMap`** — коли швидкий пошук за іменем/ключем важливіший за порядок.

Немає «кращого» чи «гіршого»; є відповідніший зараз. Спершу вголос назви свою потребу («я шукатиму за кодом» / «я друкуватиму по черзі»), і колекція сама підкаже себе. Цей простий діалог економить половину зайвих роздумів.

## Вектор як простір для змінних кількостей

Крім пошуку, `Vec` слугує зручним «контейнером динамічної кількості»: воно росте, стискається, переміщують елементи. Це твоя «кишеня», куди можна скласти багато.

```rust
let mut log: Vec<String> = Vec::new();
log.push("старт".to_string());
log.push("середина".to_string());
log.pop(); // прибрали останній запис
```

Такі списки є всюди: історії дій, повідомлення, черги невеликих кроків. `Vec` — мабуть, найзручніший друг Rust для змінних кількостей: дешево, зрозуміло, виразно. Поки думаєш про дані — пусти список на розмову першим.

## Маленька вправа із колекціями

Для закріплення, зроби спокійний крок: створи `HashMap<String, u32>`, додай кілька слів і їхніх лічильників, потім пройдися по них і надрукуй. Після цього порахуй суму через ітератор.

```rust
let mut counts = std::collections::HashMap::new();
counts.insert("сон".to_string(), 3);
counts.insert("зірка".to_string(), 2);
let total: u32 = counts.values().sum();
println!("усього: {total}");
```

Це маленька вечеря колекцій: додати, підсумувати, надрукувати. Ти щойно тримав у руках три базові рухи словника. Завтра вони стануть звичкою, якщо повторюватимуться тихо.

## Медитація на ніч

Сьогодні ми тримали в руках коробки з багатьма предметами: вектор для порядку, словник для швидкої відповіді, множину для унікальних вечорів. І ми дізналися, що ітератор — це те, що вміє перебрати все по черзі, із перетвореннями на ходу.

Кожна з цих коробок — це спосіб думати про безліч речей як про одну. Хтось тримає все, хтось шукає одне, хтось пам'ятає про неповторність. А мова — завжди поруч: не дає індексу впасти, не дозволяє писати в книзі, яку читають.

> Коробка росте, коли їй треба,
> словник відповідає на кожне ім'я,
> множина не повторює вдруге.
> Є спосіб тримати багато —
> і не загубити нічого.
